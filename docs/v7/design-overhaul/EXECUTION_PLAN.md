# Canonical Shelf v7 — Visual Overhaul Execution Plan

1. Inventory current v7 visible shell and critical surfaces against v5 experiential strengths and v4 scholarly-depth references.
2. Establish design thesis, non-goals, and prototype comparison criteria.
3. Produce at least three materially distinct prototype directions before production code.
4. Present the three directions to the human decision-maker with explicit tradeoffs and no hidden preferred implementation.
5. Record the selected direction or approved hybrid in a Design Intent Artifact.
6. Only after selection, make production implementation nodes eligible.
7. Implement the selected direction in coherent slices: global shell/tokens → Home/Course → Study Focus → Bible → Practice → Topics/Guide → utilities → responsive/motion/craft.
8. Validate each slice functionally and visually with representative real content and learner state.
9. Reopen the prototype gate if implementation evidence requires a material change to the selected direction.
10. Merge only after the complete site-level experience is coherent, current capabilities are preserved, and applicable release checks pass.

## Human gate
The prototype-selection node is human-controlled. Production UI implementation is blocked until the user explicitly selects one prototype or an explicitly described hybrid.
